# ТЗ: PHP-библиотека для VK API

## Цель и границы

Реализовать небольшую типизированную библиотеку для отправки сообщений, получения диалогов и данных пользователей. Основа — присланное тестовое задание, результат — открытый GitHub/GitLab-репозиторий с Composer-пакетом.

На [странице ВШЭ](https://miem.hse.ru/imsit/projects_recruitment_26) PHP-проект описан для MAX. В этом ТЗ используется **VK API**, поскольку его прямо требует тестовое задание. Поддержка MAX не входит в объём.

PHP 8.1+, `declare(strict_types=1)`, PSR-12, автозагрузка PSR-4. Без фреймворка и контейнера DI. Готовый VK SDK для реализации вызовов не используется.

## Публичный интерфейс

```php
public function sendMessage(int $userId, string $message, array $options = []): int;
public function getDialogs(int $offset = 0, int $count = 10): DialogCollection;
public function getUser(int $userId): User;
```

- `sendMessage` вызывает `messages.send` и возвращает ID сообщения. По умолчанию получатель — `$userId`; для беседы допускается `options['peer_id']` с VK peer ID. Дополнительные параметры ограничены документированным списком: `peer_id`, `random_id`, `attachment`, `keyboard`, `disable_mentions`. Токен, версия API и имя метода через `options` не переопределяются.
- `random_id` можно передать явно; иначе библиотека создаёт ненулевое случайное целое. При внутренних повторах одного запроса значение сохраняется. Для повтора вызова самим приложением вызывающий код сохраняет и повторно передаёт тот же ID.
- `getDialogs` сохраняет имя из задания, но обращается к актуальному `messages.getConversations`. В [официальном SDK VK](https://github.com/VKCOM/vk-php-sdk/blob/master/src/VK/Actions/Messages.php) получение диалогов представлено именно этим методом. Устаревший `messages.getDialogs` не вызывается.
- `DialogCollection` содержит общее число диалогов и список объектов `Dialog`, поддерживает перебор. Поля `Dialog`: `peerId`, `type`, `unreadCount`, `lastMessage` (строка или `null`). Тип диалога — enum `user`, `chat`, `group`.
- `getUser` вызывает `users.get` с полем `photo_100`, возвращает `User` с полями `id`, `firstName`, `lastName`, `avatarUrl` (строка или `null`). Пустой ответ — `UserNotFoundException`.
- Неверные аргументы, включая отрицательный offset, count вне 1–200 и неположительный userId, отклоняются до HTTP-запроса через `InvalidArgumentException`. Peer ID беседы проверяется отдельно. Текст или вложение должны быть непустыми.

## Простая структура

- `VKClient` — три публичных метода, подготовка параметров и преобразование ответа в объекты.
- `HttpClientInterface` и реализация на cURL — POST по HTTPS, таймауты, возврат статуса, заголовков и тела. HTTP-клиент передаётся в конструктор `VKClient`.
- `AccessToken` — непустой токен в памяти, также передаётся в конструктор. Вызывающее приложение получает его из переменной окружения или собственного хранилища; библиотека не записывает токен на диск.
- `User`, `Dialog`, `DialogCollection` — типизированные объекты результата.
- Небольшая иерархия исключений для ошибок транспорта, авторизации, доступа, лимита запросов, API и некорректного ответа.

Версия VK API задаётся параметром конструктора с документированным значением по умолчанию. Новые методы добавляются через общий механизм запроса и разбора ответа, без копирования HTTP-кода.

## Ошибки и повторные попытки

1. Разбирать как HTTP-статус, так и JSON: VK может вернуть `error` при HTTP 200. Ошибки API содержат исходный код, сообщение и имя метода, но не токен и не полный запрос.
2. Ошибка авторизации переводится в `AuthenticationException`, отказ доступа — в `AccessDeniedException`; код 188 из условия также покрывается отдельной проверкой. Неизвестный код сохраняется в общем `ApiException`.
3. Сетевые ошибки, HTTP 420/429/5xx и временные ошибки VK (например, 6 и 10) повторяются. Ошибки доступа, авторизации и входных данных не повторяются.
4. Максимум три попытки вместе с первой. Паузы перед повторами — 0,5 и 1 секунда; корректный `Retry-After` учитывается с верхним пределом 30 секунд. В тестах ожидание заменяется поддельной функцией.
5. После исчерпания попыток выбрасывается соответствующее исключение. Параметры сообщения, включая `random_id`, между попытками не меняются.
6. Некорректный JSON или неожиданная структура ответа вызывают `UnexpectedResponseException`, без молчаливого возврата пустого результата.

Токен передаётся в теле POST-запроса. Проверка TLS включена, таймауты соединения и ответа ограничены. Пользовательские данные и токен не записываются в логи. OAuth-сервер, обновление токена и автоматическое получение прав не входят в задачу.

## Тесты и документация

PHPUnit, без настоящего токена и внешней сети. Обязательные сценарии:

- Успешная отправка, правильные параметры и сохранение `random_id` при повторе.
- Получение пользователя, отсутствие пользователя и необязательного аватара.
- Получение нескольких диалогов и пустой страницы, типы возвращаемых объектов и параметры пагинации.
- Сетевой сбой с успешным повтором и с исчерпанием попыток.
- Отказ доступа, неверный токен, неизвестная ошибка API; проверка отсутствия повторов для постоянных ошибок.
- HTTP 429 и временная ошибка API при HTTP 200; `Retry-After` и предел попыток.
- Некорректный JSON, неожиданный ответ, неверные аргументы и запрещённые ключи `options`.

README содержит описание, требования, установку через `composer require <vendor>/<package>` с реальным именем пакета после его выбора, пример получения токена сообщества с нужными правами, загрузку токена из окружения, примеры всех трёх методов, перечень публичных методов и исключений, правила повторов и запуск тестов. Если пакет ещё не опубликован, отдельно указана установка из VCS через Composer; не обещать работающий пакет в Packagist заранее.

## Приёмка

В чистом окружении PHP 8.1+ проходят `composer install`, PHPUnit и проверка PSR-12. Основные успешные и ошибочные ветки покрыты тестами. В репозитории есть `composer.json`, исходный код, тесты, README, лицензия и пример без секретов. Достаточно одной небольшой библиотеки; бот, сервер и демонстрационная веб-страница не требуются.
